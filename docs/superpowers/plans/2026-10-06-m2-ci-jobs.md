# M2 — Lint and Test as Separate CI Jobs

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each PR shows two results, `lint` and `test`. Each check is a separate step,
so a failure shows which check failed. The test job shows a code coverage report.

**Architecture:** One workflow, `.github/workflows/ci.yml`, replaces `tests.yml`. The
jobs `lint` and `test` run in parallel. A new push to a PR cancels the run of the older
commit.

**Tech Stack:** GitHub Actions, `shivammathur/setup-php` with PCOV, PostgreSQL 18
service container, Pest.

**Spec:** `docs/superpowers/specs/2026-09-28-event-booking-design.md` (section 11).

## Global Constraints

- The actions have exact commit SHAs, the same as in `tests.yml`.
- The `lint` job needs no database.
- The `test` job uses a PostgreSQL service container. It has no Redis service, because
  the tests use the `array` and `sync` drivers. A Redis service comes with the first
  test that needs Redis.
- The coverage report goes to the job summary. There is no minimum percentage.
- A new push to a PR cancels the run of the older commit. Runs on `main` always finish.
- `composer ci:check` does not change. Developers use it locally.

## Review Focus

1. **Two results.** The PR shows `ci / lint` and `ci / test`.
2. **Failures are clear.** Each check of the `lint` job is a separate step.
3. **Coverage.** The summary of the run shows the coverage report.

### Task 1: Workflow

**Files:**

- Create: `.github/workflows/ci.yml`
- Delete: `.github/workflows/tests.yml`

- [ ] **Step 1: Write `ci.yml`**

The `lint` job: install the Composer and npm packages, generate the Wayfinder routes
(`php artisan wayfinder:generate --with-form`, the TypeScript checks need them), then
one step for each check: Pint (`composer lint:check`), PHPStan
(`composer types:check`), `npm run check` and `npm run types:check`.

The `test` job: the PostgreSQL service and the database variables from `tests.yml`,
PHP with `coverage: pcov`, `.env` and the app key, `npm ci` and `npm run build` (the
pages in the tests load the Vite manifest), then
`vendor/bin/pest --colors=never --coverage-text=coverage.txt`. A last step writes `coverage.txt` to
`$GITHUB_STEP_SUMMARY`.

```yaml
concurrency:
    group: ci-${{ github.ref }}
    cancel-in-progress: ${{ github.event_name == 'pull_request' }}
```

- [ ] **Step 2: Verify**

Run: `docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint:latest`
Expected: no output, exit code 0.

Run the coverage command locally with Xdebug:
`docker compose exec -e XDEBUG_MODE=coverage app vendor/bin/pest --coverage-text=/tmp/coverage.txt`
Expected: the tests pass, and the file starts with "Code Coverage Report".

- [ ] **Step 3: Commit**

```bash
git add .github/workflows/
git commit -m "ci: run lint and test as separate jobs"
```
